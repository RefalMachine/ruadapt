# Подготовка шардированного корпуса для CPT и SFT

`data.train_file` и `data.val_file` принимают путь, glob или список путей/globs.
Локальные globs раскрываются в отсортированный список. Повтор одного файла из-за
пересечения шаблонов отклоняется. JSON/JSONL можно смешивать между собой, TXT имеет
отдельный загрузчик для CPT. SFT использует JSON/JSONL. Обе factories передают
`data.cache_dir` загрузчику Arrow; max_train_samples/max_val_samples ограничивают
число исходных документов до токенизации. Это не streaming training: исходные
данные и промежуточные результаты материализуются в Arrow cache на диске.

Все пути ниже — нейтральные примеры. Подставляйте реальные пути в локальную копию
конфига под `local/` (каталог исключён из Git), а не в публикуемый шаблон.
JSON содержит буквальные пути: переменные shell вроде `$SHARED_ROOT` в его строках
автоматически не раскрываются.

```json
"data": {
  "train_file": "/scratch/project/data/legal_domain_split/train/part-*.jsonl",
  "val_file": "/scratch/project/data/legal_domain_split/val/part-*.jsonl",
  "cache_dir": "/scratch/project/workdir/hf-cache/legal_cpt_dense",
  "preprocessing_num_workers": 8
}
```

Не требуется склеивать part-00000.jsonl ... part-00417.jsonl. Если validation не
нужна, можно непосредственно передать исходный glob в train_file и не задавать
val_file. Для контроля качества train и val подготавливаются один раз на уровне
документов, до любой нарезки и packing. Разделение уже готовых packs допускает
попадание частей одного документа в оба split.

## Подготовка train и val

Из корня репозитория, в одном процессе (не через torchrun):

```bash
python3 -m ruadapt.training.datasets.split_jsonl \
  --input '/scratch/project/data/legal_domain_dataset/part-*.jsonl' \
  --output-dir /scratch/project/data/legal_domain_split \
  --val-fraction 0.001 \
  --seed 1337
```

Команда требует только стандартную библиотеку Python. Она последовательно читает
JSONL, держит в памяти один документ и сохраняет все поля записей. Создаёт train/
и val/ с отдельным выходным shard на каждый входной файл. Источники не меняются.
Выходной каталог должен отсутствовать; существующие результаты не перезаписываются.
Нужно место примерно под дополнительную копию исходных данных, отдельно от Arrow cache.

Назначение split определяется SHA256 от seed и поля text (с удалением пробелов по
краям), а не порядковым номером строки. Одинаковые тексты во всех исходных shards
попадают в один split. Порядок строк и файлов не меняет назначение документа.
Это не дедупликация: повторные записи сохраняются, но не пересекают train/val.

Если есть общий ID дела/документа для нескольких версий или частей, используйте
`--group-field case_id` (либо фактическое имя поля). Все записи одного ID попадут
в один split. Поле должно присутствовать и быть непустым. Группировка по ID не
гарантирует группировку одинаковых текстов с разными ID; при необходимости такие
связи нужно объединить при подготовке групп. Хеш текста не обнаруживает близкие
дубликаты, редакции документов или смысловую связь разных текстов.

Доля 0.001 означает ожидаемые 0.1% документов, не точное число документов или
токенов. При 418 shards по 10 тысяч строк это ориентировочно 4180 validation
документов; фактические числа будут в manifest. Если нужны временная или доменная
валидация, этот случайный по хешу split их не заменяет.

`manifest.json` содержит алгоритм, seed, поле группировки, входные пути и счётчики
по файлам и split. Он появляется только после успешного завершения; не используйте
частично записанный каталог без него. Повреждённый JSON или отсутствующее поле
группировки останавливают подготовку с файлом и номером строки. Пустой train/val
также считается ошибкой; после исправления входов используйте новый выходной каталог.

## Подготовленный dataset и обучение

Подготовка и обучение доступны через общий CLI библиотеки. Скопируйте подходящий
пример из `configs/examples/` в `local/cpt.json`, задайте модель, train/val/cache
и отдельный `training.output_dir`. Пути в JSON — буквальные строки:
переменные shell в них не раскрываются.

Подготовить Arrow cache без загрузки весов модели:

```bash
python3 -m ruadapt.training.train --config local/cpt.json --data_prep_only
```

Для передачи подготовленных данных следующему заданию используйте
`--prepared_dataset_dir` (пример ниже), затем укажите полученный каталог в
`data.prepared_dataset_dir` конфига обучения. Выполняйте подготовку одним
родительским процессом в том же runtime, где будет обучение. Загрузка tokenizer
и TrainingArguments требует зависимостей обучения; BF16/TF32-конфиг может
требовать видимый GPU даже в `data_prep_only`.

Обычное обучение из подготовленного конфига:

```bash
python3 -m ruadapt.training.train --config local/cpt.json
# Несколько GPU на одном узле:
python3 -m torch.distributed.run --standalone --nproc_per_node=8 \
  -m ruadapt.training.train --config local/cpt.json
```

Для нескольких узлов настройте torchrun rendezvous, node rank и число узлов
средствами своего планировщика. Библиотека не выбирает Slurm partition, account,
контейнер или cluster cache. При смене world size пересчитайте global batch:
world size × microbatch × gradient accumulation (для полных updates).

Конкретная юридическая CPT-серия, её JSON, Slurm-launcher и throughput sweep
перенесены в отдельный репозиторий `research/experiments/legal_cpt/`.
Инструкции отправки и зависимости `afterok` находятся в `research/docs/SLURM.md`.
Код библиотеки не импортирует экспериментальные инструменты из этого репозитория.

Manifest хранит ссылки на существующие Arrow shards: для обычного dense CPT
вторая копия всего корпуса не создаётся. Он содержит параметры подготовки,
состояние входных файлов, хеш кода и список готовых Arrow-файлов с размерами,
временем изменения и количеством строк. Изменение данных, кода или policy,
отсутствующий/изменённый cache приводят к ошибке; автоматической пересборки внутри
training нет. Проверка файлов использует size/mtime, не полный хеш корпуса.
Для remote URLs фиксируется адрес, а неизменность удалённого содержимого этим
manifest не проверяется. Используйте одинаковые контейнер и версии библиотек.
Не очищайте/перезаписывайте cache и PREP_DIR до завершения зависимых запусков.
Для смены параметров подготовки запустите подготовку в новый PREP_DIR.

Экспорт из CLI отдельно от Slurm:

```bash
python3 -m ruadapt.training.train --config local/cpt.json \
  --data_prep_only --prepared_dataset_dir /path/to/shared/prepared/cpt
```

Затем укажите этот каталог в `data.prepared_dataset_dir` локального JSON для
обучения. Экспорт рассчитан на общий Arrow путь (явные packing/sequence), а не
старый tensor-backed PackedDataset. Не публикуйте manifest и runtime-копии:
они содержат реальные абсолютные пути.

## Скорость dense packing

`data.preprocessing_num_workers` управляет и токенизацией, и новым dense packer.
После tokenization CPT без substitution сразу переходит к `dense Arrow`; прежний
промежуточный `Packing` map не нужен. Сначала выводится точное число токенов и packs,
затем прогресс `Dense packing (256 packs/task)`. Для whole/none остаётся generator.

Воспроизводимая локальная проверка:

```bash
python -m dev.benchmark_packing --documents 10000 --workers 1 4
```

На синтетических 40 577 747 токенах (9 907 packs, L=4096) последовательный эталон
занял 17.53 с, Arrow с одним worker — 0.73 с, с четырьмя — 0.50 с.
Проверены одинаковые input_ids, labels и segment_lengths. Замер включает укладку
и запись Arrow, но не токенизацию; небольшой набор помещается в page cache,
принудительного fsync нет. Это локальный результат, не прогноз времени для
кластерного корпуса: на десятках миллиардов токенов пропускная способность общего
диска и память всех workers могут стать главным ограничением. Полный кластерный
замер после изменения пока не проведён.
